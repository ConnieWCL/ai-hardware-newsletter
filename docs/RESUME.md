## 一、简历条目（推荐版，可直接复制）

**AI 硬件情报 Agent**（个人项目 · Python / GitHub Actions / LLM）　　2026.08 – 至今

个人自建的每日产业情报系统：自动追踪 13 个中英文信源的智能硬件与 AI 硬件动态，经双层关键词过滤与两级去重后，由 LLM 按七栏结构（含独立「新形态智能硬件」栏目，国内/国外分栏）生成中文日报，每天上午 10 点投递至邮箱并自动发布为公开存档站，零服务器、日均成本 ¥0。

- 设计双层关键词过滤（核心词决定入选资格 + 泛化词加分 + 黑名单一票否决）与两级去重（URL 规范化 + Shingle-Jaccard 聚类），将每日 58 条候选收敛为 9–16 条，5–7 分钟读完
- 构建三层防幻觉机制（输入材料约束 / JSON Schema 输出 / 溯源链接白名单校验），上线首日即拦截模型编造条目；LLM 服务商官方退役当天完成配置化迁移，代码零改动
- 以 GitHub Actions 实现零服务器调度与月度 token 预算护栏，产出自动发布为静态存档站，网页与邮件共用同一套渲染模板
- 针对"国外新闻占比过低"问题，定位根因在选材层而非提示词层，设计英文材料配额（≥40%）与信源分层机制（T1 可直接引用 / T2 需交叉验证 / T3 不单独引用），保证国际板块不缺失

链接：github.com/ConnieWCL/ai-hardware-newsletter　·　conniewcl.github.io/ai-hardware-newsletter　·　aihardwarenewsletter.hiconnie.com

## 二、Bullet 变体（按岗位侧重替换）

**技术 / 平台 / 算法向**
- 实现两级去重：URL 规范化（O(n)，消除"同文不同参"）叠加标题 2-gram Jaccard 聚类（阈值 0.6）；评估并否掉了 embedding 相似度方案（需额外 API 调用，收益不抵成本）
- 针对 LLM 输出不确定性设计三层校验与三层降级：输出强约束为 JSON Schema、link 白名单过滤编造条目、解析失败可诊断；单源失效跳过、LLM 不可用出有版式速览版、发送失败落盘补发，保证日报零缺席
- 提供商无关的架构设计：LLM 通过 OpenAI 兼容接口调用，换服务商只需改环境变量，不动代码；已实测完成一次服务商退役迁移

**产品经理向**
- 定义七栏目信息架构（今日速览 / 新形态智能硬件 / 国内新品 / 国外新品 / 技术芯片 / 融资招聘 / 一句话点评）与四条质量红线（可溯源、去重、限长 ≤16 条、宁缺毋滥），用产品手段解决"信息过载导致第三周弃用"的核心流失问题
- 针对低声量新品类（AR/VR 眼镜、智能戒指、录音卡、AI 挂件）在纯热度排序下必然被手机/PC 类新闻淹没的问题，在选材层设计品类配额机制而非仅调提示词，从架构上保证重点品类的信息供给
- 采用「先验证需求、再工程实现」路径：先用平台工具跑通需求验证（栏目结构、信息密度、信源取舍），再自建工程化版本，避免带着错误假设开工
- 求职导向的信息策略：国内厂商动态优先级高于同级国际新闻，中文源 6 + 英文源 7，国外条目 ≥30% 硬约束，全文中文输出
- 基于真实使用反馈迭代：发现国外板块缺失后，未停留在"改提示词"的表层修复，而是溯源到选材层配额问题并从架构上解决

**通用精简版（两行）**
- 自建每日情报 Agent：13 信源采集 → 双层过滤 + 两级去重 → LLM 结构化摘要 → 邮件投递 + 公开存档站，零服务器、日均成本 ¥0
- 通过三层防幻觉校验与月度预算护栏控制 LLM 不确定性，上线首日即拦截编造条目；三层降级保证日报零缺席

## 三、30 秒口头介绍脚本

> "我最近在做的一个个人项目，是一个**AI 硬件情报 Agent**。背景是我求职转型期间需要每天跟进产业动态，但市面上的日报太泛，所以我自己做了一个：每天自动从 13 个中英文信源抓候选，先做去重和相关性过滤，再让大模型按七个栏目结构化摘要，早上 8 点半发到我邮箱，同时生成一个公开存档网页。"
> "设计上我最在意两件事：一是**AI 只用在规则做不好的环节**——采集、去重、事实校验全是确定性代码，大模型只负责判断和表达，所以成本是零、幻觉也可控；二是**不能断更**，所以做了三层降级，模型挂了也会出一份有版式的速览版。"
> "目前每天 58 条候选收敛到 9 到 16 条，零服务器，日均成本 ¥0。"

## 五、面试高频问题索引（完整答案见面试资料包第 06 节）

- **为什么不用现成工具 / 直接问 ChatGPT？** → 规则锁定事实边界，LLM 只在边界内表达
- **幻觉怎么控制？** → 三层闸门，首日实测拦截
- **成本？会不会失控？** → ¥0；月度台账护栏，未绑信用卡
- **失败过吗？** → 四个真问题（服务商退役 / 中文源损坏 / 关键词放水 / 推理模型输出截断）
- **去重为什么不用向量/embedding？** → 成本收益分析 + 短文本场景；给出 MinHash/LSH 升级路径
- **国外新闻占比问题怎么发现的？** → 根因在选材层不在提示词层（**最想讲的案例**）
- **你怎么衡量做得好不好？** → 诚实：硬约束 + 效率指标已有，主观指标待补评测集
- **用户量上去了怎么办？** → 区分"该做"与"当前规模的过度设计"
- **你自己每天真的在看吗？** → 诚实回答：正在试用第 N 天，已根据内容质量调整过信源与过滤规则
