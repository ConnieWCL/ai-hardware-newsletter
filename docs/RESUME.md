## 一、简历条目（推荐版，可直接复制）

**AI 硬件情报 Agent**（个人项目 · Python / GitHub Actions / LLM）　　2026.08 – 至今
个人自建的每日情报系统：自动追踪 13 个中英文信源的智能硬件与 AI 硬件动态，经相关性过滤与两级去重后由 LLM 结构化摘要，每天 08:30 投递至邮箱并自动发布为公开存档站，日均成本 ¥0。

- 设计双层关键词过滤（核心词资格制 + 泛化词加分 + 黑名单否决）与两级去重（URL 规范化 + Shingle-Jaccard 聚类），将每日 58 条候选收敛为 9 条，5 分钟读完
- 构建三层防幻觉机制（输入材料约束 / JSON Schema 输出 / 溯源链接白名单校验），上线首日即拦截模型编造条目；LLM 服务商退役当天完成配置化迁移，代码零改动
- 以 GitHub Actions 实现零服务器调度与月度 token 预算护栏，产出自动发布为静态存档站，网页与邮件共用同一套渲染模板

链接：github.com/ConnieWCL/ai-hardware-newsletter　·　conniewcl.github.io/ai-hardware-newsletter

## 二、Bullet 变体（按岗位侧重替换）

**技术 / 平台 / 算法向**
- 实现两级去重：URL 规范化（O(n)，消除同文不同参）叠加标题 2-gram Jaccard 聚类（阈值 0.6），候选池 < 300 条时毫秒级完成；评估并否掉了 embedding 相似度方案（额外 API 调用、百毫秒级延迟，收益不抵成本）
- 针对 LLM 输出不确定性设计三层校验与三层降级：输出强约束为 JSON Schema、link 白名单过滤编造、解析失败可诊断；单源失效跳过、LLM 不可用出有版式速览版、发送失败落盘补发，保证日报零缺席

**产品经理向**
- 定义五栏目信息架构（今日速览 / 新品规格拆解 / 技术芯片动向 / 融资招聘信号 / 一句话点评）与四条质量红线（可溯源、去重、限长 ≤12 条、宁缺毋滥），用产品手段解决"信息过载导致第三周弃用"的核心流失问题
- 采用「先验证需求、再工程实现」路径：先用平台工具跑通需求验证（栏目结构、信息密度、信源取舍），再自建工程化版本，避免带着错误假设开工
- 求职导向的信息策略：国内厂商动态优先级高于同级国际新闻，中文信源 6 + 英文信源 7，全文中文输出

**通用精简版（两行）**
- 自建每日情报 Agent：13 信源采集 → 双层过滤 + 两级去重 → LLM 结构化摘要 → 邮件投递 + 公开存档，零服务器、日均成本 ¥0
- 通过三层防幻觉校验与月度预算护栏控制 LLM 不确定性，上线首日即拦截编造条目

## 三、30 秒口头介绍脚本

> "这是我给自己做的一个 AI 硬件情报 Agent。求职期间我需要每天跟进产业动态，但市面上的日报太泛，所以我自己做了一个：每天从 13 个中英文信源抓候选，先做去重和相关性过滤，再让 LLM 按五个栏目结构化摘要，早上 8 点半发到我邮箱，同时生成一个公开存档网页。"
> "设计上我最在意两件事：一是**AI 只用在规则做不好的环节**——采集、去重、事实校验全是确定性代码，LLM 只负责判断和表达，所以成本是零、幻觉也可控；二是**不能断更**，所以做了三层降级，LLM 挂了也会出一份有版式的速览版。"
> "目前每天 58 条候选收敛到 9 条，单次 4 千 token，成本 ¥0。"

## 五、面试高频问题索引（完整答案见 PRD 第 6 节）

- **为什么不用现成工具 / 直接问 ChatGPT？** → 规则锁定事实边界，LLM 只在边界内表达
- **幻觉怎么控制？** → 三层闸门，首日实测拦截
- **成本？会不会失控？** → ¥0；月度台账护栏，未绑信用卡
- **失败过吗？** → 四个真问题（服务商退役 / 中文源损坏 / 关键词放水 / 推理模型输出截断）
- **用户量上去了怎么办？** → 批量发送 + MinHash/LSH + 重排模型，当前规模属过度设计
- **你自己每天真的在看吗？** → 诚实回答：正在试用第 N 天，已根据内容质量调整过信源与过滤规则
